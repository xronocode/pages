title: "fix(shortcut): classify tap vs hold by key event time, not dequeue time"
description: "Merged upstream: Handy #2097 — a tap-vs-hold misclassification on first activation. The coordinator executes Effect::Start inline, and the first activation after startup spends about 400ms initializing the microphone; a key release queued behind that block was stamped at dequeue time, so a short tap measured past the hold threshold, was classified as a hold, and stopped the just-started recording with zero samples (#2089). The fix stamps each key event when the sender observes it and measures holds edge-to-edge from those stamps; debouncing uses edge time too, so two distinct presses are no longer falsely coalesced when the queue drains late. The reporter confirmed the fix on Windows the day the PR opened, cjpais promised to pull it in soon, and after one gentle nudge it landed 2026-11-11 as squash 56c7e217 — eight weeks after opening, the maintainer's usual pace, with the issue auto-closed."
